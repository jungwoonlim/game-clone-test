# 개발이 어떤 식으로 진행되는가

이 문서는 "Godot으로 이런 게임을 만들 때 실제로 뭘 어떤 순서로 하게 되는가"를
이 프로젝트를 예시로 정리한 것입니다.

---

## 1. Godot의 기본 모델

Godot은 **노드(Node)를 트리로 조립**하고, 그 트리를 **씬(`.tscn`) 파일로 저장**하는
구조입니다. 각 노드에 스크립트(`.gd`)를 붙이면 그 노드가 행동을 갖습니다.

이 게임에 쓰인 노드는 다섯 종류가 전부입니다.

| 노드 | 역할 |
| --- | --- |
| `Node2D` | 좌표를 가진 일반 컨테이너. 루트(`Main`), 과일 보관함(`Fruits`), 투하기(`Dropper`) |
| `RigidBody2D` | 엔진이 물리를 굴려주는 강체. 과일 하나 |
| `StaticBody2D` | 움직이지 않는 충돌체. 항아리 벽/바닥 |
| `CollisionShape2D` | 위 두 개에 붙는 실제 충돌 모양 (원/사각) |
| `CanvasLayer` + `Label` | 카메라와 무관하게 화면에 고정되는 UI |

게임 코드는 결국 **"매 프레임 `_process(delta)`에서 상태를 갱신하고, 물리는
엔진에 맡기고, 충돌 시그널이 오면 반응한다"** 는 루프입니다.

## 2. 이 게임의 실제 흐름

```
_ready()            항아리/UI 준비, 최고점 로드, 첫 과일을 Dropper에 얹음
   │
_process(delta)     ├ 투하 쿨타임 감소 → 끝나면 다음 과일 preview 생성
   │                ├ 키보드 좌우 입력으로 Dropper 이동
   │                └ 데드라인 위에 머무는 과일 검사 (게임오버 판정)
   │
_unhandled_input()  마우스 이동 → Dropper 이동 / 클릭 → _drop()
   │
_drop()             preview 과일을 Dropper에서 떼어 Fruits 밑으로 옮기고
   │                freeze 해제 → 이 순간부터 물리 엔진이 굴림
   │
(물리 엔진)          낙하 → 충돌
   │
Fruit._on_body_entered()   같은 단계 과일끼리 닿음 → request_merge 시그널
   │
Game._merge()       둘 제거, 한 단계 큰 과일 생성, 점수 가산
```

핵심 설계 두 가지만 짚으면:

- **과일은 자기가 뭘 만났는지만 알리고, 판단은 게임이 한다.** `Fruit`은
  `request_merge` 시그널만 쏘고 실제 생성/삭제/점수는 `game.gd`가 처리합니다.
  덕분에 과일은 점수 규칙을 전혀 모릅니다.
- **밸런스는 전부 테이블 하나.** `fruit_data.gd`의 배열에 한 줄씩 추가하면
  단계가 늘어납니다. 코드를 고칠 필요가 없습니다.

## 3. 반복 개발 루프

실제 작업은 이 사이클을 계속 도는 것입니다.

1. **에디터에서 F5** — 바꾼 걸 즉시 눈으로 확인 (게임 개발은 "느낌"이 스펙이라
   실행해보는 게 유일한 검증입니다)
2. **수치 조정** — 중력, 반지름, 질량, 쿨타임을 바꿔가며 손맛을 맞춤
3. **리모트 씬 트리 확인** — 실행 중 에디터 `Remote` 탭에서 살아있는 노드를
   그대로 열어볼 수 있습니다. 과일이 몇 개 남았는지, 좌표가 어딘지 바로 보입니다
4. **헤드리스 테스트** — 눈으로 못 잡는 회귀는 `tools/smoke_test.gd`로

```bash
godot --headless --path . --script res://tools/smoke_test.gd
```

## 4. 실제로 밟았던 함정 (중요)

이 클론을 만들면서 **물리가 폭발하는 문제**를 겪었고, 같은 장르를 만들면 반드시
만나게 되는 문제라 기록해 둡니다.

### 증상
과일 16개만 떨어뜨렸는데 게임 오버. 계측해보니 과일이 초속 1591px로 항아리 밖으로
날아가 좌표 `(724, -311)` 같은 곳에 있었습니다.

### 원인
1. **병합 시 겹침 폭발** — 두 과일이 합쳐지면 *더 큰* 과일이 그 자리에 생깁니다.
   생성 순간 주변 과일들과 깊게 겹치고, 물리 솔버가 이 겹침을 한 번에 밀어내면서
   과일을 로켓처럼 쏘아 올립니다. 질량비가 클수록(반지름² 기준 60:1) 더 심합니다.
2. **전역 데드라인 타이머** — "누구든 데드라인 위에 있으면 타이머 증가"로
   짰더니, 날아다니는 서로 다른 과일들이 릴레이로 타이머를 계속 살려놔서
   실제로는 아무도 2초를 못 채웠는데 게임 오버가 났습니다.

### 해결
- `Fruit._integrate_forces()`에서 **속도 상한(1500px/s)과 좌표 클램프**를 걸었습니다.
  물리적으로 정확하진 않지만, 캐주얼 퍼즐에서는 "절대 항아리를 못 벗어난다"가
  정확성보다 훨씬 중요합니다.
- 벽 콜리전을 화면 위쪽(`y=-320`)까지 **보이지 않게 연장**해 깔때기처럼 만들었습니다.
- 질량을 `r²`에서 `r^1.5`로 낮춰 질량비를 60:1 → 21:1로 완화했습니다.
- 데드라인 타이머를 **과일별(`Fruit.danger_time`)로 분리**했습니다.
- 게임 오버 후 `_merge()`가 조기 리턴하도록 막았습니다. (안 그러면 게임오버
  화면 뒤에서 물리가 계속 돌며 점수가 올라갑니다 — 실제로 그랬습니다)

교훈: **강체 물리 퍼즐은 "물리를 믿지 말고 상한을 걸어라".**

## 5. 여기서 더 붙인다면

난이도 순으로:

- **사운드** — `AudioStreamPlayer`를 병합 시 재생. 단계별로 피치를 올리면 즉시 그럴듯해집니다
- **병합 이펙트** — `GPUParticles2D` 한 번 터뜨리기, `Tween`으로 새 과일 스케일 팝
- **다음 과일 미리보기 개선** — 지금은 `_draw()`로 원만 그림. 실제 과일 씬을 축소해 보여주기
- **모바일 대응** — 터치 입력은 이미 처리되어 있음. `export_presets`에 Android 추가
- **리더보드/업적** — 스팀 붙일 거면 `docs/STEAM_RELEASE.md` 참고
- **아트 교체** — `_draw()` 대신 `Sprite2D`로. 이때 `fruit.tscn`에 `Sprite2D`를 추가하고
  `fruit_data.gd`에 텍스처 배열을 한 줄 더 넣으면 끝납니다

## 6. 저장소 운영

이 저장소는 클론 프로젝트를 여러 개 담습니다.

- 프로젝트마다 최상위 폴더 하나 (`suika-game/`, 다음은 `tetris-clone/` 등)
- 각 폴더는 **독립적인 Godot 프로젝트** — 서로 의존하지 않습니다
- 각자 `.gitignore`로 `.godot/`(임포트 캐시)와 빌드 산출물을 제외합니다
- `.gd.uid`, `*.import` 파일은 **커밋해야 합니다** (Godot 4.4+ 리소스 참조 무결성)
