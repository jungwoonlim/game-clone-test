# 02. 시스템 명세

## 검증 상태 라벨

원작 수치는 출처마다 충돌합니다. 아래 표기를 따릅니다.

| 라벨 | 뜻 | 대응 |
| --- | --- | --- |
| ✅ | 여러 출처가 일치 | 그대로 구현 |
| ⚠️ | **출처 간 충돌** | 일단 구현하되 ROM 검증 대상 |
| ❓ | 미검증 / 추정 | 플레이스홀더. 반드시 검증 |

> **원칙: 모든 공식과 상수는 `core/battle/formulas.gd` 한 파일과 Resource에만 존재합니다.**
> 나중에 정확한 값을 확인하면 데이터만 고치면 되고, 로직은 손대지 않습니다.

## 1. 스탯

| 스탯 | 설명 |
| --- | --- |
| 레벨 | 1 ~ 30 ✅ |
| 힘 (Strength) | 공격력의 기반 |
| 민첩 (Agility) | 방어력·선공·회피의 기반 |
| 최대 HP / 현재 HP | |
| 최대 MP / 현재 MP | |
| EXP | 누적 경험치. 상한 65535 ✅ |
| 골드 | |

**파생 스탯**

```
공격력 = 힘 + 무기 공격력                    ✅
방어력 = floor(민첩 / 2) + 갑옷 + 방패        ✅
```

몬스터는 별도의 방어력 스탯 없이 **민첩을 방어에 사용**합니다. ✅

## 2. 전투

### 2-1. 흐름

```
전투 개시
  ↓
선공 판정 ─── 몬스터 선공 시 몬스터 턴부터
  ↓
[턴 루프]
  플레이어 커맨드 선택 ── 싸운다 / 주문 / 도구 / 도망
  ↓
  행동 해결 → 메시지 출력
  ↓
  몬스터 행동 결정(행동 테이블) → 해결 → 메시지 출력
  ↓
  종료 판정 (몬스터 HP 0 / 플레이어 HP 0 / 도망 성공)
  ↓
승리 → EXP·골드 획득 → 레벨업 판정 → 주문 습득 메시지
```

**턴은 완전히 결정적이어야 합니다.** 난수는 주입된 시드에서만 뽑습니다. 헤드리스 시뮬레이션으로 밸런스를 검증하려면 같은 시드에서 같은 결과가 나와야 합니다.

### 2-2. 선공 판정

```
몬스터 민첩 * random(0..255) / 256  >  플레이어 민첩 / 2   → 몬스터 선공
```
⚠️ 계수가 출처마다 다릅니다 (`민첩/4` vs `민첩/2`).

### 2-3. 통상 공격 데미지

```
# 공격자 → 방어자
유효방어 = (방어자가 몬스터) ? floor(몬스터 민첩 / 2) : 플레이어 방어력

if 공격력 > 유효방어:
    데미지 = random( floor((공격력 - 유효방어) / 4),
                     floor((공격력 - 유효방어) / 2) )
else:
    # 약공격 분기
    데미지 = random( 0, floor((공격력 + 1) / 6) )
```

- 강공격 분기 구조 ✅ — "유효방어보다 공격력이 4 높아야 최소 1 데미지가 보장된다", "방어 4당 데미지 1 감소"라는 두 진술과 일치합니다
- 약공격 분기의 계수 `/6` ⚠️ — `/16`이라는 출처도 있습니다

### 2-4. 회심의 일격 (크리티컬)

```
확률 = 1/32,  방어 무시,  데미지 = random(공격력 * 0.5, 공격력)
```
⚠️ **출처 충돌.** 다른 문서는 `확률 = 민첩/64, 데미지 = 통상 * 2`라고 합니다.
위 정설 쪽을 먼저 구현하되 검증 대상으로 둡니다. 보스에게는 크리티컬이 발생하지 않습니다 ✅.

### 2-5. 도망

```
성공확률 기반값에 (플레이어 민첩 - 몬스터 민첩) 보정
```
❓ 정확한 계수 미검증. 보스 전투에서는 도망 불가 ✅.

## 3. 주문 (10종)

| 습득 Lv | 이름(원작 영문) | MP | 효과 |
| --- | --- | --- | --- |
| 3 ✅ | Heal | 4 ❓ | HP 회복 random(10~17) ⚠️ |
| 4 ✅ | Hurt | 2 ✅ | 적 데미지 random(3~10) ⚠️ |
| 7 ✅ | Sleep | 2 ✅ | 적 수면 |
| 9 ✅ | Radiant | 3 ❓ | 던전 시야 확대, 걸음 수에 따라 감소 |
| 10 ✅ | Stopspell | 2 ✅ | 적 주문 봉인 |
| 12 ✅ | Outside | 6 ❓ | 던전 탈출 |
| 13 ✅ | Return | 8 ❓ | 시작 마을로 귀환 |
| 15 ✅ | Repel | 2 ❓ | 일정 걸음 동안 약한 적 인카운터 차단 |
| 17 ✅ | Healmore | 10 ❓ | HP 회복 random(85~100) ⚠️ |
| 19 ✅ | Hurtmore | 5 ✅ | 적 데미지 random(30~45) ⚠️ |

⚠️ **시전자에 따라 위력이 다릅니다.** 몬스터가 쓰는 Hurt는 5~12, Hurtmore는 58~65라는 출처가 있습니다. 즉 `SpellData`에 시전자별 위력을 따로 두는 편이 안전합니다.

### 상태이상 판정

```
성공 = random(0..255) >= 대상의 해당 저항값
```
- 수면/주문봉인 모두 **대상별 저항 스탯**으로 판정 ✅
- 플레이어는 주문봉인에 50% 저항, 수면에는 저항 없음 ⚠️
- 수면은 최소 1턴 보장, 이후 매 턴 1/3 확률로 각성 ⚠️
- 방어구에 따라 Hurt 계열 1/3 경감 ⚠️

## 4. 성장

### EXP 테이블 (레벨 2~30 도달 누적치)

```
7, 23, 47, 110, 220, 450, 800, 1300, 2000, 2900,
4000, 5500, 7500, 10000, 13000, 16000, 19000, 22000, 26000, 30000,
34000, 38000, 42000, 46000, 50000, 54000, 58000, 62000, 65535
```
⚠️ 복수 출처가 일치하지만 ROM 대조 전까지는 검증 대상으로 둡니다.

### 스탯 성장

레벨별 **고정 테이블**입니다 (성장 공식이 아님) ✅.
원작은 여기에 **이름 기반 보정**이 걸립니다 — 이름에서 유도한 값으로 4개 스탯 중 2개가 감산됩니다 ⚠️. 이 클론에서는 **1단계에서 구현하지 않고**, 기본 테이블만 씁니다. 재현 여부는 나중에 결정합니다.

레벨별 힘/민첩/최대HP/최대MP 실수치는 ❓ — 전량 검증 필요 (→ `03-DATA.md`).

## 5. 장비

무기 / 갑옷 / 방패 각 **1칸씩** ✅. 교체만 가능하고 슬롯 확장은 없습니다.

- 무기 → 공격력 가산
- 갑옷 → 방어력 가산, 일부는 Hurt 계열 경감 및 독 지형 데미지 무효
- 방패 → 방어력 가산

판매가는 구입가의 절반 ❓.

## 6. 필드 / 맵

### 이동

**그리드 기반**입니다. 논리 좌표는 항상 정수 타일 좌표이고, 화면상의 부드러운 이동은 뷰 레이어의 보간일 뿐입니다. (→ `04-ARCHITECTURE.md`)

```
입력 → 목표 타일 계산 → 통행 가능 판정 → 논리 좌표 갱신 → 걸음 수 +1
                                              ↓
                                    뷰가 시그널 받아 보간 애니메이션
```

### 지형

| 타입 | 통행 | 인카운터 | 비고 |
| --- | --- | --- | --- |
| 평지/초원 | O | 보통 | |
| 숲 | O | 높음 | |
| 언덕/산지 | O | 높음 | |
| 늪 | O | 보통 | 진입 시 HP 데미지 ✅ |
| 물/바다 | X | - | |
| 벽/바위 | X | - | |
| 계단/문 | O | - | 맵 전환 트리거 |

### 인카운터

```
걸음마다: random(0..255) < 지형별 인카운터 확률  → 전투 개시
```
지형·지역별 **몬스터 출현 테이블**에서 추첨 ✅. Repel 효과 중에는 일정 레벨 이하 몬스터가 제외됩니다 ✅.

### 던전 시야

던전에서는 플레이어 주변 N타일만 보입니다. 횃불 사용 또는 Radiant 주문으로 N이 커지고, 걸음 수에 따라 감소합니다 ✅.

## 7. 마을 시설

| 시설 | 동작 |
| --- | --- |
| 무기/방어구점 | 구입·판매. 장비는 1칸 교체 |
| 도구점 | 소모품 구입·판매. 인벤토리 상한 있음 ✅ |
| 여관 | 골드 지불 → HP/MP 전회복 |
| 왕 (성) | **세이브**. 사망 시 이 지점에서 부활 |

### 사망 처리

HP 0 → 소지 골드 **절반 상실** → 세이브 지점에서 부활 ✅. 게임 오버 화면은 없고 진행은 유지됩니다.

## 9. UI

- **메시지 창** — 하단 고정. 한 글자씩 출력, 버튼으로 다음 페이지
- **커맨드 창** — 원작식 세로 메뉴. 필드에서는 `말한다/조사한다/주문/도구/장비/스테이터스`
- **전투 커맨드** — `싸운다/주문/도구/도망`
- **스테이터스 창** — 좌상단 상시 표시 (레벨/HP/MP/골드/EXP)

UI는 전부 뷰 레이어입니다. `core/`는 "무엇을 물어봐야 하는지"만 알고, 창을 어떻게 그리는지는 모릅니다.
