# 11 — 한글화

영어로 만든 게임에 한국어를 넣은 기록입니다. 결과보다 **어디를 건드렸고 어디를
건드리지 않았는지**가 요점입니다.

> **core에 들어간 한국어는 한 글자도 없습니다.** core가 바뀐 곳은 딱 한 군데 —
> 전투 이벤트가 이름 대신 **id**를 싣게 한 것입니다. 그건 번역을 위한 타협이
> 아니라, core가 여태 표기를 결정하고 있었다는 걸 한글화가 드러낸 것에 가깝습니다.
> 문구를 고르는 코드는 전부 `view_2d/`에 있습니다.

## 무엇을 어디에 두었나

| 있는 곳 | 들어 있는 것 |
| --- | --- |
| `assets/i18n/strings.csv` | `keys,en,ko` 세 열. **모든** 문구의 원본 |
| `assets/i18n/*.translation` | Godot 임포터가 CSV에서 만든 결과물 |
| `view_2d/i18n/loc.gd` | `Loc.t()` — 키 조회 + 서식 + 조사 처리 |
| `view_2d/ui/battle_text.gd` | 전투 이벤트 → 문장 |
| `core/` | 아무것도. id와 숫자뿐 |

키는 세 갈래로 나뉩니다.

1. **UI 문구** — `MSG_*`, `MENU_*`, `BT_*` 처럼 의미로 이름 붙인 키.
2. **데이터 이름** — id에서 만듭니다. 아이템 `herb` → `ITEM_HERB`,
   몬스터 `m_slime` → `MONSTER_M_SLIME`. `.tres`는 한 줄도 안 바뀌었습니다.
3. **NPC 대사** — `.tres`가 문장 대신 키를 들고 있습니다 (`NPC_KING_1A`).
   데이터는 언어를 모르는 편이 낫고, 어차피 id만 들고 있던 파일들입니다.

## core를 건드리지 않기 위해 바꾼 것 하나

`BattleEvent`가 **이름 대신 id**를 싣도록 바꿨습니다.

```gdscript
# 전  events.append(BattleEvent.new(Kind.SPELL_CAST, true, 0, spell.display_name))
# 후  events.append(BattleEvent.new(Kind.SPELL_CAST, true, 0, spell.id))
```

전에는 core가 `"Heal"`이라는 **영어 단어**를 뷰에 건네고 있었습니다. 그건 core가
표기를 결정하고 있었다는 뜻입니다. 이제 `&"heal"`을 건네고, 뷰가
`호이미`라고 읽을지 `Heal`이라고 읽을지 정합니다.

`tools/test_architecture.gd`에 규칙으로 박아 두었습니다 — **core의 어떤 파일도
`Loc.` / `tr(` / `TranslationServer`를 언급할 수 없습니다.**

## 조사

한국어는 앞 글자의 받침에 따라 조사가 갈립니다. 문장을 조각으로 조립할 수 없다는
뜻입니다.

```
MSG_FOUND_ITEM    ko    {item}#을(를) 손에 넣었다!
```

번역자는 한국어가 이미 갖고 있는 모호한 표기(`을(를)`)를 그대로 쓰고, `#`으로
"여기서 갈린다"고 표시만 합니다. `Loc.resolve_josa()`가 앞 글자를 보고 고릅니다.

| 앞 글자 | 판단 | 결과 |
| --- | --- | --- |
| 약초 | `초` 종성 없음 | 약초**를** |
| 강철검 | `검` 종성 ㅁ | 강철검**을** |
| 3 | 「삼」 종성 ㅁ | 3**이** |
| Broad Blade | 알 수 없음 | Broad Blade**을(를)** |

마지막 줄이 중요합니다. 판단할 수 없으면 **표기를 그대로 둡니다** — 그게 읽는
법을 모를 때 한국어가 실제로 쓰는 방식이고, 억지로 하나를 고르는 것보다 정직합니다.

## 글꼴

`ThemeDB.fallback_font`(Open Sans)에는 한글이 없습니다. 다른 에셋은 전부
생성했지만 한글 글꼴만은 생성할 수 없습니다 — 11,172자를 11픽셀에서 읽히게
만드는 일이니까요.

Noto Sans KR(SIL OFL 1.1)을 받아 **이 게임이 실제로 쓰는 380자로 잘라** 넣습니다.
2.4MB → 52KB. `tools/build_font.py`가 받고 자르고, `tools/build_font.gd`가 Theme을
만듭니다.

글자 크기는 9px에서 **11px**로 올렸습니다. 한글은 그 아래로 내려가면 자모가
서로 붙습니다. 라틴 문자도 같이 키웠습니다 — 언어마다 다른 크기를 들고 다니느니
한 벌로 맞추는 편이 낫습니다.

### 커서와 막대를 글자로 그리지 않게 된 이유

메뉴 커서는 `▶`, 볼륨 막대는 `■`/`□` 문자였습니다. **Noto Sans KR 한국어 서브셋에는
도형 문자가 없습니다.** 개발 중에 멀쩡히 보였던 건 컨테이너에 우연히 CJK 글꼴이
깔려 있어서 시스템 폴백이 대신 그려 줬기 때문이고, 깨끗한 설치에서는 전부 빈
네모였을 겁니다.

셋 다 `draw_colored_polygon` / `draw_rect`로 바꿨습니다. 글꼴에 기대지 않고,
이 크기에서는 픽셀에 정확히 떨어지기까지 합니다.

그리고 이 부류의 버그를 두 번 겪지 않도록 검사를 넣었습니다 — **문자열 표의 모든
글자가 우리가 배포하는 글꼴 안에 있는지** 확인합니다.

## 검증

`tools/test_presentation.gd`가 한글화에 대해 보는 것:

- 모든 키가 **두 언어 모두**에 비어 있지 않은 값을 갖는가
- 두 언어가 **같은 서식 자리**를 쓰는가 (`{gold}`가 한쪽에만 있으면 화면에 중괄호가 찍힙니다)
- 뷰 코드에 적힌 모든 키 문자열이 표에 있는가 (사운드 이름 대조와 같은 방식)
- 모든 아이템·몬스터·주문·맵이 이름 행을 갖는가, 모든 NPC 대사 키가 존재하는가
- 조사가 실제로 풀리는가, 그리고 **어느 언어에서도 `#`이 화면에 남지 않는가**
- 표의 모든 글자가 글꼴에 있는가

`tools/smoke_view.gd`는 **2D·2.5D × 영어·한국어 네 조합**으로 전체 플레이스루를
돕니다. 한쪽 언어에서만 창을 넘치는 메뉴는 이렇게만 잡힙니다.

## 언어 추가하기

1. `strings.csv`에 열을 하나 더한다 (`ja`).
2. `project.godot`의 `locale/translations`에 경로를 더한다.
3. `view_2d/settings.gd`의 `LOCALES` / `LOCALE_KEYS`에 더한다.
4. `tools/build_font.py`를 다시 돌린다 — 새 글자에는 글꼴이 필요하다.

코드는 건드리지 않습니다. 조사 처리는 한국어에만 적용되고, 다른 언어의 문장에는
`#`이 없으므로 아무 일도 하지 않습니다.
